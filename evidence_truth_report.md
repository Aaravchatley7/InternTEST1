# Evidence Truth Report

## Purpose

The Evidence Truth Report explains how verification decisions are produced, what evidence was used, how confidence was calculated, and how outputs can be reconstructed using ledger artifacts.

The goal is to ensure that every validation result generated by the BHIV Multi-Input Intelligence Platform can be explained, reproduced, and audited.

# Validation Path

## Step 1

Input Collection

User submits:

* Name
* DOB
* Phone
* Aadhaar Number
* PAN Number

---

## Step 2

OCR Extraction

System extracts text using:

* EasyOCR
* Tesseract Fallback

Output:

```json
{
    "ocr_engine": "easyocr",
    "text": "..."
}
```

---

## Step 3

Field Extraction

System extracts:

* Name
* DOB
* Aadhaar Number
* PAN Number

Output:

```json
{
    "name": "...",
    "dob": "...",
    "aadhaar_number": "...",
    "pan_number": "..."
}
```

---

## Step 4

Validation

Comparison between:

* User Data
* Extracted Data

Output:

```json
{
    "field_results": {
        "name": true,
        "dob": true,
        "aadhaar": true,
        "pan": false
    }
}
```

---

## Step 5

Confidence Calculation

Confidence is derived from weighted validation signals.

Weights:

| Field        | Weight |
| ------------ | ------ |
| Name         | 0.35   |
| DOB          | 0.20   |
| Aadhaar      | 0.25   |
| PAN          | 0.15   |
| Phone        | 0.05   |
| Completeness | 0.10   |

# Ledger Storage

Each completed verification request is stored in:

```text
ledger/
├── trace_id_1.json
├── trace_id_2.json
├── trace_id_3.json
```

Each ledger artifact contains:

* Request Snapshot
* Extraction Snapshot
* Validation Snapshot
* Confidence Snapshot
* Evidence Snapshot
* Final Response

---

# Replay Reconstruction

Replay Engine retrieves:

```text
trace_id
```

and reconstructs:

```json
{
    "request": {},
    "extraction": {},
    "validation": {},
    "confidence": {},
    "evidence": {},
    "output": {}
}
```

without executing OCR, validation, confidence scoring, or evidence generation again.

---

# Deterministic Guarantee

Replay is deterministic because:

* Data is read from stored ledger artifacts
* No workflow steps are re-executed
* No OCR is re-run
* No LLM calls are made
* No confidence recalculation occurs

Therefore:

* Same input trace_id
* Same replay result
* Every time

---

# Human Reviewer Reconstruction Process

A reviewer can:

1. Obtain trace_id
2. Query Replay API
3. Retrieve stored ledger artifact
4. Inspect validation decisions
5. Inspect confidence reasoning
6. Inspect evidence package
7. Reconstruct final output

without rerunning the workflow.
